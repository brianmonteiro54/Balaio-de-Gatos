09 · Alucinação

Quando o modelo inventa.

Alucinação não é "modelo com bug". É consequência natural de como LLMs funcionam: eles preveem o token mais provável, não consultam fonte. Se a resposta certa não está nos pesos, ele inventa algo plausível. Veja exemplos clássicos e as 4 estratégias de mitigação.

Exemplo clássico
"Liste 3 papers do Geoffrey Hinton sobre redes neurais com DOI"
Resposta alucinada:
  1. "Backpropagation Revisited" (2018) · DOI: 10.1234/567890 ❌
  2. "Capsule Networks for Vision" (2019) · DOI: 10.5678/111213 ❌
  3. "Distributed Representations" (2020) · DOI: 10.9876/141516 ❌

⚠️ Os papers parecem plausíveis mas os DOIs são inventados. O modelo nunca consultou nenhuma base. Cuidado em domínio jurídico, médico, acadêmico.

11 · Chain-of-Thought (CoT)

"Pense passo a passo" muda o jogo.

Em problemas que exigem raciocínio multi-step, mandar o modelo "pensar antes de responder" melhora drasticamente a acurácia. Compare lado a lado a mesma pergunta com e sem CoT.

❌ Sem CoT
Prompt: "Tenho 3 caixas com 4 gatos cada. Cada gato come 2 latas/dia. Tenho 24 latas. Sobra ração até o fim do dia?"
Resposta direta:

"Sim, sobra ração."

❌ Errado. Vamos checar: 3×4 = 12 gatos. 12×2 = 24 latas/dia. 24÷24 = 0 sobra (zerou exatamente). Resposta certa seria "não sobra, zerou".
✅ Com CoT
Prompt: "Tenho 3 caixas com 4 gatos cada... Pense passo a passo antes de responder."
Raciocínio do modelo:

Passo 1: Total de gatos = 3 × 4 = 12.
Passo 2: Consumo diário = 12 × 2 = 24 latas.
Passo 3: Estoque = 24 latas. Sobra = 24 - 24 = 0.
Resposta: Não sobra, mas dá certinho.

✅ Correto. Forçar o raciocínio explícito evitou o atalho mental e a alucinação.

💡 Quando usar CoT

  • Matemática e contas com múltiplas etapas
  • Lógica e silogismos
  • Planejamento de tarefas
  • Análise de causa e efeito

⚠️ Custo: CoT aumenta os tokens da resposta (porque o raciocínio fica visível). Use só quando vale o custo extra.

12 · Prompt Chaining × ReAct

Duas formas de orquestrar múltiplas chamadas.

Quando uma chamada só não resolve, você precisa encadear. Chaining é sequencial e fixo. ReAct é o modelo decidindo o próximo passo dinamicamente, com ferramentas externas.

🔗 Prompt Chaining

Sequência fixa de prompts

Você define os passos. Saída do passo 1 vira entrada do passo 2. Determinístico, fácil de debugar, mas inflexível.

1 Extrair "Liste os tópicos do texto"
→
2 Resumir "Resume cada tópico em 1 frase"
→
3 Formatar "Monte tabela markdown"
Use quando: fluxo conhecido, passos bem definidos, precisa de previsibilidade.
⚡ ReAct (Reason + Act)

Modelo decide as ações

O modelo alterna Pensamento → Ação → Observação em loop, usando ferramentas externas (APIs, busca, calculadora). Flexível e poderoso, mas pode loopar ou alucinar passos.

🧠 Thought "Pra responder, preciso saber o estoque atual"
🛠️ Action chama API get_stock(item="ração")
👁️ Observation resposta = "12 caixas em estoque"
🧠 Thought "Agora calculo se dá pra duas semanas"
✅ Final answer "Sim, com 12 caixas dá pra 14 dias"
Use quando: caminho não é conhecido a priori, precisa de ferramentas externas. Base do Bedrock Agents.

Sem RAG vs com RAG.

Mesmo modelo. Mesma pergunta. Compare a resposta. RAG recupera trechos relevantes da sua base e injeta no prompt antes do FM responder. Não treina o modelo, só dá contexto.

16 · Chunking

O tamanho do chunk muda tudo.

Chunks pequenos = mais precisão mas falta de contexto. Chunks grandes = mais contexto mas ruído. Overlap entre chunks evita perder informação no corte. Mexe nos sliders e veja como o documento é dividido.

💡 Heurísticas práticas pro AIF-C01:
  • FAQ / chatbot: chunks de 200–400 tokens, overlap 10–20%
  • Documentos legais/técnicos: chunks 500–1000 tokens, overlap 20%
  • Código: chunks por função/classe (chunking semântico)
  • Bedrock Knowledge Bases: configura tudo isso pra você (default 300 tokens, overlap 20%)
17 · Cola final pra prova

Tudo o que decorar.

🪆 Hierarquia

IA ⊃ ML ⊃ Deep Learning. GenAI é uma aplicação que usa Deep Learning (Transformers).

🎓 Tipos de aprendizado

Supervisionado (com rótulos), não-supervisionado (sem rótulos), reforço (recompensa/punição).

📊 Tarefas ML

Classificação (categórica), regressão (numérica), clustering (agrupamento sem rótulo).

🎯 Over × Under

Underfitting: erra no treino e no teste. Overfitting: acerta no treino e erra no teste.

🤖 LLM × SLM

LLM: capaz, caro, alto. SLM: rápido, barato, especializado. Edge → SLM. Raciocínio → LLM.

🔤 Tokens

Unidade de processamento e cobrança. 1 token ≈ 4 chars ou 0.75 palavra. Pricing é por token.

📦 Context window

Limite TOTAL de tokens (input + output). Se passa, é cortado. Modelos modernos chegam a 200k+ tokens.

🌡️ Temperature

0–0.3: determinístico, factual. 0.7+: criativo, variado. Top-k limita o universo de tokens.

👻 Alucinação

Inventa plausível. Mitiga (não elimina) com RAG, prompt restritivo, A2I, validação de output.

🎲 Shots

Zero: 0 exemplos. One: 1. Few: 2–5. Mais exemplos = mais tokens = mais $.

🧠 Chain-of-Thought

"Pense passo a passo". Melhora muito em raciocínio multi-step. Custo: aumenta tokens da resposta.

🔗 Chaining × ReAct

Chaining: você define a sequência. ReAct: modelo decide ações com ferramentas. Base de Bedrock Agents.

📚 RAG

Recupera trechos da sua base e injeta no prompt. Não treina o modelo. AWS: Bedrock Knowledge Bases.

✂️ Chunking

Quebra docs em pedaços (300–1000 tokens) com overlap (10–20%). Tamanho impacta precisão × contexto.

📐 Pipeline RAG

Ingestão → Chunk → Embed → Store (offline). Query → Retrieve → Generate (online).

📏 Boas práticas

Específico, papel, formato, few-shot, restrições, quebrar em passos, iterar e versionar.

🎯 Pegadinhas que caem na prova

  • "Dados que mudam toda semana" → RAG. "Adaptar tom de voz" → Fine-tuning. "Ensinar jargão de domínio" → Continued pre-training.
  • "Resposta consistente e factual" → temperature baixa. "Brainstorm criativo" → temperature alta.
  • "Modelo decorou o treino" → overfitting. Solução: regularização, mais dados, modelo simples.
  • "Modelo precisa decidir o que fazer dinamicamente, com ferramentas" → ReAct (e Bedrock Agents).
  • "Sumarizar capítulo de livro" → cuide da janela de contexto antes. Pode precisar chunking + RAG.
  • Alucinação se MITIGA, não ELIMINA. Resposta com "elimina 100%" quase sempre está errada.
  • Few-shot ≠ fine-tuning. Few-shot é só prompt. Não muda o modelo.
  • "Single-shot" e "one-shot" são a mesma coisa: 1 exemplo. Few-shot começa em 2.
