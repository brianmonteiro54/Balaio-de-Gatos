📡 boto3 · Query API

Como sua aplicação consulta o Kendra em produção:

# Query no índice Kendra
import boto3
client = boto3.client("kendra")

resp = client.query(
    IndexId="abc-12345",
    QueryText="quanto tempo demora pra dar férias?",
    AttributeFilter={
        "AndAllFilters": [
            {"EqualsTo": {"Key": "_source_uri",
              "Value": {"StringValue": "confluence"}}}
        ]
    },
    PageSize=10
)

# 3 tipos de resultado:
for r in resp["ResultItems"]:
    if r["Type"] == "ANSWER":
        ...  # resposta extraída
    elif r["Type"] == "QUESTION_ANSWER":
        ...  # FAQ match
    elif r["Type"] == "DOCUMENT":
        ...  # documento padrão
📊 Quando preferir Kendra vs OpenSearch?

🧠 Kendra

  • Pergunta em linguagem natural
  • Documentos não estruturados (PDF, Word)
  • Você quer resposta direta, não link
  • FAQ + Q&A automatizado out-of-the-box
  • Sem time de ML

🔍 OpenSearch

  • Logs, métricas, time-series
  • Busca facetada (filtro por categoria)
  • Você precisa de full control
  • Vector search pra RAG próprio
  • Custo importa muito

04 · Etapas do Pipeline de ML

As 7 etapas que rodam toda vez que você re-treina.

Um pipeline de ML é código que automatiza o ciclo de vida: ingestão → preparação → treino → avaliação → deploy. Quando o pipeline está bom, você re-treina a cada semana clicando 1 botão. Clica em cada etapa pra ver os detalhes e o serviço AWS correspondente.

05 · Análise Exploratória (EDA)

Antes de modelar, olhe o dado de cara.

EDA é a fase onde você descobre que 30% dos clientes têm idade negativa, que vendas tem outlier de R$ 9 milhões, que duas variáveis são 99% correlacionadas. Pular EDA = treinar lixo. 🔬 O que EDA responde?

  • Distribuição: minhas vendas seguem normal ou cauda longa?
  • Outliers: tem ponto absurdo afetando a média?
  • Correlação: quais variáveis se mexem juntas? Pode haver redundância.
  • Missing: onde tá faltando dado e por quê?
  • Cardinalidade: campos categóricos com 100k valores únicos? Vai gerar feature explosion.
  • Skewness: campo enviesado pra um lado? Considere log-transform.

🔍 Kendra
enterprise search

NLU embutida + answer extraction + 40+ conectores. Caro mas paga quando ROI da busca é alto.

data ingestion
"De onde vem o dado?"
Batch (Glue, DMS) ou streaming (Kinesis, Firehose). Sempre passa por quality checks.
🎯 Definir metas
fase 1
"Que problema de negócio resolve?"
KPI mensurável + restrições (latência, custo, fairness) + critério de sucesso.
🏗️ Desenvolver
fase 2
"Treinar e validar."
EDA → feature eng → split treino/val/teste → treino → avaliação → ajuste.
🚀 Implantar
fase 3
"Pôr em produção."
Endpoint (SageMaker), batch transform, edge (IoT). A/B test, blue/green, shadow.
📈 Monitorar
fase 4
"O modelo ainda funciona?"
Data drift, concept drift, performance drop, alertas, retreino automático.
🏭 Pipeline ML
7 etapas
"Re-treinar é 1 click."
Ingestão → Prep → EDA → Feature → Treino → Avaliação → Deploy. SageMaker Pipelines / Step Functions.
📊 EDA
exploratory analysis
"Olhar o dado antes de modelar."
describe(), histograma, scatter, correlação, missing, outliers. Pula → treina lixo.
📐 Stats básicas
numpy day 1
"Mean, mediana, std, IQR."
Mean é sensível a outlier. Mediana resiste. IQR pra detectar outliers (Q3 + 1.5×IQR).
🌡️ Data Drift
monitoring
"Os dados de hoje ainda parecem com os de treino?"
PSI, KS test, Wasserstein. Drift detectado → alarme → retreino.
🪣 Data Lake
S3 + Glue
"Tudo num lugar barato."
S3 storage + Glue catalog + Athena query. Padrão pra raw data antes de virar feature.

"O que eu levo?"
ML não é só treinar. É um ciclo de 4 fases que vira código (pipeline) e nunca termina (monitoramento). Antes de tudo: EDA, EDA, EDA.
