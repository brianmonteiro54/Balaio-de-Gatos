🐈 Quais técnicas tu vai usar?

As mais comuns, na vida real:

  • Imputação: preencher NULL com média, mediana, moda ou um valor "razoável".
  • Deduplicação: identificar e remover registros idênticos.
  • Normalização: escalas diferentes (peso em kg, idade em anos) viram uma escala comum (0-1 ou z-score).
  • Encoding: categóricos viram número (one-hot, label encoding).
  • Tratamento de outliers: gato de 30kg é típico ou erro de digitação?
💼 Por que isso importa?

O ditado "garbage in, garbage out" não é poesia, é matemática. Dado ruim → modelo ruim. Sempre. Não tem hiperparâmetro mágico que conserte um dataset bagunçado.

💡 Pra fixar: feature engineering vs feature extraction
Feature engineering (o que vimos acima)

Você, manualmente, cria features baseado no que conhece do domínio. Ex.: "filhote = idade < 12 meses".

Feature extraction (deep learning)

A própria rede neural descobre as features sozinha (ex.: CNN aprendendo a detectar bigodes em fotos de gato). Não precisa de você desenhar features à mão.

Tu fez engenharia de features lindamente. Agora vem a pergunta: onde armazenar? O time de treino precisa, o time de inferência precisa, o time de A/B testing precisa, todos querem a mesma versão. É aí que entra o SageMaker Feature Store: um repositório central de features na AWS.

🎯

🐾 Quando data augmentation é ouro?

Quando tu tem poucos dados, e coletar mais é caro: imagens médicas raras, espécies em extinção, defeitos de fábrica que aparecem 1 em 10 mil. Augmentation multiplica o que tem.

Funciona muito bem em visão computacional (rotacionar uma foto de gato e ainda é gato) e em áudio (acelerar, abafar). Em texto e dados tabulares é mais delicado: "rotacionar uma frase" não faz sentido literal, mas existem técnicas como back-translation e synonym replacement.

05 · Treinamento & Datasets de Benchmark

Como o modelo aprende, e em quê?

Treinar = mostrar exemplos repetidamente e ajustar os parâmetros internos (pesos) pra reduzir o erro. Antes, a visão de cima do fluxo geral. Depois, o zoom no loop interno que roda milhões de vezes.

🗺️ Vista de cima: o fluxo geral

Os 4 grandes blocos que todo projeto de ML passa, do dataset até a validação:

PASSO 1
📊 Dataset rotulado

Entradas (foto, texto) + saídas esperadas (rótulo). Quanto maior e mais limpo, melhor.

→
PASSO 2
🧠 Arquitetura

Escolhe o tipo de modelo: rede neural, árvore, transformer, etc.

→
PASSO 3
🔁 Loop de treino

Forward (prediz) → calcula erro → backward (ajusta pesos). Repete milhares de vezes.

→
PASSO 4
📈 Validação

Testa em dados nunca vistos. Se for bem, deploya. Se for mal, ajusta hiperparâmetros.

🔬 Zoom no Passo 3: o loop de treino, por dentro

Aqui mora a "mágica". É essa sequência de 5 passos que se repete milhões de vezes até o modelo aprender:

PASSO 1

🍽️ Mostrar o exemplo

O modelo recebe uma entrada (foto, frase, conjunto de features). O "olha esse gato aqui".

🐈→🤖forward pass
PASSO 2

🤷 Modelo chuta

Baseado nos pesos atuais (geralmente aleatórios no começo), o modelo dá uma resposta. No início é quase sempre errada.

🤖💭"cachorro?"previsão
PASSO 3

📏 Medir o erro

Compara a resposta do modelo com a resposta certa. A diferença é a loss (perda). Quanto maior, pior.

📐 erro = 0,87loss function
PASSO 4

🔧 Ajustar os pesos

O algoritmo (gradient descent, geralmente) volta atrás e ajusta os parâmetros internos do modelo pra errar menos da próxima vez.

⚙️←📉backprop
PASSO 5

🔁 Repetir milhões de vezes

Volta pro passo 1, agora com o gato 2, gato 3, ..., gato N. Quando passa por TODOS os exemplos uma vez, completou uma época.

🔄 ∞epoch loop
🧠 Modelo = matemática + dados + tempo

No fim das contas, "treinar" é só encontrar os números mágicos (os pesos) que fazem o modelo errar o mínimo possível. Não tem inteligência, não tem alma. Tem gradiente descendente repetido um zilhão de vezes. O gato adestrado é o resultado.

06 · Pré-treino continuado vs Fine-tuning

Não precisa treinar do zero. Aproveita o pronto.

Treinar um LLM do zero custa milhões de dólares e meses de GPU. Por sorte, você quase nunca precisa fazer isso. Há dois caminhos pra adaptar um modelo pronto pro seu caso:

Etapa intermediária

🌱 Pré-treino continuado

Existem várias técnicas, escolhidas por custo, dados disponíveis e objetivo:

🐈 Resumão da hierarquia de adaptação

1) Pré-treino do zero → caríssimo, raríssimo (só Big Tech faz). 2) Pré-treino continuado → caro, injeta domínio. 3) Fine-tuning → barato, ensina tarefa. 4) Prompt engineering / RAG → grátis, ajusta no momento da pergunta sem retreinar.

Regra prática: comece sempre pelo final da lista. Só sobe pra fine-tuning ou pré-treino se prompt+RAG não der conta. É barato demais ignorar.

Parte 3 · Os botões mágicos

Hiperparâmetros: aqueles botões
que mudam tudo.

Parâmetros o modelo aprende sozinho durante o treino. Hiperparâmetros, VOCÊ que define antes do treino começar. Ajustá-los bem é metade do segredo de um bom modelo. Bora mexer em cada um deles, na prática.

07 · O que são hiperparâmetros?

Os botões externos do modelo.

Imagina o modelo como um liquidificador. Os parâmetros são os ingredientes que você bota dentro (banana, leite, açúcar) e ele combina. Os hiperparâmetros são os botões fora dele: velocidade, tempo, modo pulsar. Você escolhe antes de ligar. Se errar a velocidade, vira sopa em vez de vitamina.

🔧 Hiperparâmetros de TREINO

Controlam como o modelo aprende:

  • Épocas: quantas vezes ver o dataset
  • Learning rate: quão grande é o passo no aprendizado
  • Batch size: quantos exemplos por iteração
  • Optimizer: SGD, Adam, AdamW...
  • Dropout / weight decay: regularização
🎲 Hiperparâmetros de INFERÊNCIA (LLM)

Controlam como o modelo gera resposta:

  • Temperatura: criatividade da geração
  • Top-k: quantas opções considerar
  • Top-p (nucleus): corte por probabilidade acumulada
  • Max tokens: tamanho da resposta
  • Stop sequences: onde parar
🎯 Ajuste de hiperparâmetros (Hyperparameter Tuning)

Em vez de tentar valores na mão, ferramentas como SageMaker AMT (Automatic Model Tuning) rodam vários treinos em paralelo, com combinações diferentes, e te entregam a melhor configuração. Mais detalhes no fim desta parte.

08 · Épocas (Epochs)

Quantas vezes o modelo revê o dataset?

Uma época = uma passada completa por todo o dataset de treino. Treinar com poucas épocas = modelo nem aprendeu direito (underfit). Épocas demais = modelo decora os exemplos e perde capacidade de generalizar (overfit). Mexa no slider e veja onde mora o ponto certo.

"Quantas épocas usar?"

Não tem número mágico. O ponto ideal é onde a loss de validação para de cair e começa a subir. Antes disso, o modelo ainda tá aprendendo. Depois, tá decorando os exemplos de treino e perdendo capacidade de generalizar.

Truque clássico: usar early stopping. O algoritmo monitora a loss de validação e para automaticamente quando ela começa a subir por N épocas seguidas. Você define um teto alto (ex.: 100 épocas) e deixa parar sozinho.

Sintomas de overfit:

  • Treino ótimo, validação medíocre
  • Gap entre os dois crescendo
  • Modelo memoriza exemplos específicos
No mundo real: em fine-tuning de LLM, 3-5 épocas costuma bastar. Em redes neurais profundas em CV, 50-200. Sempre olhe a curva, não chuta.
09 · Temperatura

O termômetro da criatividade.

Temperatura é um hiperparâmetro de inferência (não de treino). Ele controla o quanto a geração de um LLM é determinística vs aleatória. Baixo (0): o modelo sempre escolhe a palavra mais provável. Resposta previsível. Alto (2): ele escolhe meio na sorte. Resposta criativa, mas pode descambar pro disparate.

🐈 Prompt: "O gato preto pulou em cima do..."

Os candidatos pra próxima palavra têm probabilidades. Aumenta a temperatura e veja a distribuição achatar (mais opções viram prováveis):

0 = sempre o mais provável (determinístico). 1 = padrão. 2 = quase uniforme (caótico).
> O gato preto pulou em cima do

"Qual temperatura usar?"

Tarefas factuais (resumir contrato, responder pergunta técnica, classificar): use baixa (0 a 0.3). Você quer respostas previsíveis e estáveis. Mesmo input → mesmo output.

Tarefas criativas (escrever poesia, brainstorm, geração de variações): use alta (0.7 a 1.2). Diversidade vira virtude. Mesmo input → outputs diferentes a cada chamada.

Tarefas balanceadas (chatbot conversacional, assistente geral): use média (0.5 a 0.8). Modelos como Claude e GPT geralmente usam ~0.7 por padrão.

⚠️ Cuidado: temperatura alta aumenta o risco de alucinação. Em produção, tarefas críticas (médica, jurídica) sempre vão com temperatura baixa + verificação.

Em fine-tuning: temperatura só importa na inferência. Durante o treino, o modelo aprende as probabilidades. Na hora de gerar, você escolhe o quão "agressivo" pegar essas probabilidades.
10 · Top-k Sampling

Quantas opções o modelo considera?

Pra cada palavra que vai gerar, o LLM tem uma distribuição de probabilidade sobre milhares de tokens possíveis. Top-k diz: "considera só os k mais prováveis, ignora o resto". Mexe no slider e veja quais palavras ficam "no jogo" e quais são descartadas:

🎲 Candidatos pra "o gato é muito..."

Em verde os que o modelo pode escolher. Em cinza, os cortados pelo top-k. Sorteia entre os verdes proporcionalmente à probabilidade.

k=1 quase igual à temperatura 0 (sempre o mais provável). k=alto = mais variedade.
Massa de probabilidade considerada
87%

"Top-k vs Temperatura: qual a diferença?"

Ambos controlam aleatoriedade, mas de jeitos diferentes:

  • Temperatura: achata ou afia a curva de probabilidade inteira (mexe nas chances de todo mundo).
  • Top-k: corta a cauda da curva (descarta os candidatos improváveis).

Top-p (nucleus sampling) é um primo do top-k: em vez de "k tokens", ele pega "os tokens que somam até p% de probabilidade". Mais adaptativo.

Na prática, você combina os dois: temperatura baixa + top-k médio = saída coerente mas com alguma variedade. Temperatura alta + top-k baixo = criativo mas controlado.

Em produção: top-k tem o papel de "trava de segurança": impede que o modelo escolha uma palavra absurdamente improvável que poderia fazer a resposta descarrilar.
11 · Máximo de tokens (Max Tokens)

Quantas palavras a resposta pode ter?

Max tokens é o teto de quantos "pedacinhos de palavra" (tokens) o modelo pode gerar na resposta. Não é o tamanho exato, é o limite máximo. Importa porque: (1) controle de custo (tu paga por token), (2) controle de latência (resposta longa demora), (3) controle de comportamento (forçar respostas curtas).

"Pra que serve isso na prática?"

Sempre defina um max_tokens. Se você não definir, o modelo pode gerar um texto enorme e:

  • Te cobrar uma fortuna num único request
  • Demorar 30 segundos pra responder
  • Encher a resposta com enrolação irrelevante

Heurística boa: defina o dobro do que você acha que precisa. Pra resumir um parágrafo? 150 tokens. Pra classificar (resposta tipo "spam"/"não-spam")? 10. Pra escrever um artigo? 2000.

Tokens contam tanto na entrada quanto na saída. Modelos têm um "context window" total (ex.: 8k, 128k, 1M). Max_tokens é só o pedaço da saída.

Atenção: se a resposta é cortada no meio porque atingiu max_tokens, o modelo não "termina a frase". Ele para literalmente naquele ponto. Por isso definir um valor generoso vale mais que economizar 10 tokens.
12 · Ajuste de Hiperparâmetros (HPO)

Como achar a combinação certa?

Você não vai testar à mão 1000 combinações de épocas × learning rate × batch size × dropout. Existem algoritmos pra explorar o espaço de hiperparâmetros e encontrar o melhor conjunto. No SageMaker chama-se Automatic Model Tuning (AMT).

🟦 Grid Search

Testa todas as combinações de uma grade pré-definida. Exaustivo. Caro. Garantido, mas explode em custo se você tem muitos hiperparâmetros.

força bruta
🎲 Random Search

Sorteia combinações aleatoriamente. Mais barato que grid, surpreendentemente bom na prática. Costuma ser o ponto de partida.

surpresa boa
🧠 Bayesian Optimization

Aprende com tentativas anteriores: "essa região foi boa, vou explorar mais lá". Convergência rápida com poucas tentativas.

esperto · padrão
🧬 Hyperband / Population

Treina muitos modelos em paralelo, mata os ruins cedo, foca recursos nos promissores. Ótimo pra deep learning.

paralelo
🐾 Quando vale o esforço?

HPO automatizado faz sentido quando: (1) você tem budget de GPU pra rodar dezenas de treinos; (2) já tem um baseline funcionando e quer espremer os últimos 5% de performance; (3) o modelo vai pra produção e cada décimo de acurácia importa. Pra prototipagem rápida, valores padrão + intuição costumam bastar.

😿 Underfitting

O que é: modelo tão simples que nem captura o padrão dos dados de treino.

Sintomas:

  • Erro alto no treino E no teste
  • Erros parecidos nos dois conjuntos
  • Curva de loss flat ou pouco decrescente

🛠️ Como tratar underfitting?

  • 🧠Aumentar a complexidade do modelo (mais camadas, mais parâmetros)
  • 🔧Engenharia de features mais rica
  • ⏱️Treinar por mais épocas
  • 📐Reduzir regularização (dropout, weight decay)
  • 🔄Tentar uma arquitetura diferente

🙀 Overfitting

O que é: modelo decorou os exemplos de treino, mas falha em dados novos.

Sintomas:

  • Erro baixo no treino, alto no teste
  • Gap grande entre as duas curvas
  • Modelo "memoriza" exemplos específicos

🛡️ Como tratar overfitting?

  • 📚Coletar mais dados (a primeira opção, sempre)
  • 🌀Data augmentation
  • 🎯Regularização (L1, L2, dropout)
  • ⏹️Early stopping (parar antes de decorar)
  • 🧹Reduzir complexidade do modelo
  • 🔀Cross-validation pra detectar antes

🧹 Pré-processamento
limpar dados crus
"Como tirar o lixo do dataset?"
Imputar nulls, deduplicar, normalizar escalas, padronizar formato e categorias, tratar outliers.
🔧 Feature Engineering
criar novas colunas
"Como dar mais info pro modelo?"
Derivar features das existentes: idade de data, flags binárias, bucketização, one-hot, z-score.
📦 SageMaker Feature Store
online + offline
"Onde guardar features?"
Repositório central AWS. Online = baixa latência inferência. Offline = histórico em S3 pra treino.
🌀 Data Augmentation
multiplicar exemplos
"Tenho pouco dado, e agora?"
Variações sintéticas: rotação, flip, brilho, ruído (CV). Back-translation, synonyms (NLP).
🏋️ Loop de treino
forward → loss → backprop
"Como o modelo aprende?"
5 passos: mostra exemplo → chuta → mede erro → ajusta pesos → repete um zilhão de vezes.
📚 Benchmarks
ImageNet, MMLU, GLUE...
"Como comparar modelos?"
Datasets públicos padrão. ImageNet (visão), MMLU (LLM), GLUE (NLP), HumanEval (código).
🌱 Pré-treino continuado
CPT · texto bruto
"Como injetar conhecimento?"
Continua treinando modelo base com texto do seu domínio (médico, jurídico). Sem rótulos.
🎯 Fine-tuning
tarefa específica
"Como ensinar comportamento?"
Treina modelo em pares input→output rotulados. LoRA é o favorito (barato). Centenas/milhares de exemplos.
🔧 Hiperparâmetros
você define
"Parâmetro vs hiperparâmetro?"
Parâmetros = pesos aprendidos. Hiperparâmetros = botões externos que VOCÊ ajusta (épocas, learning rate, temperatura).
⏱️ Épocas
passadas pelo dataset
"Quantas vezes ver o dado?"
Poucas = underfit. Muitas = overfit. Use early stopping pra parar automaticamente no ponto certo.
🌡️ Temperatura
0 a 2, inferência LLM
"Quão criativa a resposta?"
Baixa (0-0.3): factual. Média (0.5-0.8): balanceado. Alta (0.7-1.2): criativo. Acima de 1.5: caos.
🎲 Top-k
k candidatos só
"Quantas opções considerar?"
Modelo escolhe entre os k tokens mais prováveis, descarta o resto. Trava de segurança contra absurdos.
📏 Max tokens
teto da saída
"Quão longa a resposta pode ser?"
Controle de custo + latência. Sempre defina. Lembra: 1 token ≈ 0.75 palavras em pt-br.
🧭 HPO
Grid · Random · Bayesian
"Como achar a melhor combo?"
SageMaker AMT roda vários treinos em paralelo. Bayesian é o esperto, Random é o barato bom.
😿 Underfitting
modelo simples demais
"Erra no treino E no teste?"
Aumentar complexidade, mais features, mais épocas, menos regularização.
🙀 Overfitting
decorou o treino
"Acerta treino, erra teste?"
Mais dados, augmentation, regularização (dropout, L1/L2), early stopping, modelo mais simples.
🐾 Resumão da aula
"Pipeline completo?"
Limpe (preproc) → enriqueça (features) → guarde (FS) → multiplique (augment) → treine (loop) → afie (hyperparams) → cuide (over/underfit).
