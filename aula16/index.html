Parte 1 · O humano não saiu da equação

Quando a IA não tem certeza,
ela chama o humano.

Modelo bom é modelo que sabe quando não sabe. Pra isso existe Amazon A2I (Augmented AI): orquestra revisão humana em decisões de ML que têm baixa confiança ou alto impacto.

Fluxo Augmented AI ponta a ponta

O A2I não toma a decisão, ele orquestra. Define os thresholds de confiança, distribui as tarefas pro pool humano (próprio, vendor da AWS Marketplace ou Mechanical Turk) e devolve a decisão pra aplicação. O ciclo de feedback alimenta o retreino do modelo.

📜 Pipeline de linhagem ponta a ponta

1

Origem

Documento entra no S3 com metadata: autor, data, versão, hash.

2

Indexação

Bedrock Knowledge Bases chunka, embedda e preserva o link de cada chunk pro arquivo de origem.

3

Retrieval

Modelo recebe os chunks junto com seus metadados como contexto. Não tem como "esquecer" a fonte.

4

Resposta

Output inclui source citations: arquivo, página, trecho. Auditoria feliz.

🗂️

SageMaker Lineage Tracking

Rastreia automaticamente datasets, modelos, treinamentos e deploys. Quem treinou, com qual dado, em que data.

📋

SageMaker Model Cards

Documenta o modelo: dados de treino, casos de uso, limitações conhecidas, métricas de bias.

📚

Bedrock Knowledge Bases

Retorna source citations nativamente em cada resposta: qual documento, qual chunk.

📜

AWS Glue Data Catalog

Catálogo central de datasets. Descoberta, esquema, ownership e linhagem de tabelas.

09 · Cola final pra prova

O que decorar.

🧑‍⚖️ Amazon A2I

Augmented AI. Orquestra human-in-the-loop pra decisões de ML. Threshold de confiança baixo → humano revisa. Cai sempre que a questão fala "revisão humana".

🔍 SHAP / LIME / Clarify

Ferramentas de explicabilidade (XAI). SHAP atribui pesos baseados em teoria dos jogos. LIME aproxima local. Clarify é o serviço AWS que implementa SHAP.

📇 AWS AI Service Cards

Documentação pública de cada serviço de IA da AWS: capacidades, limitações, contextos de teste. Exemplo de transparência.

⚖️ Trade-off

Mais simples = mais explicável e menos performático. Mais complexo = inverso. Decisão regulada/crítica → modelo mais simples ou caixa preta + Clarify.

🛡️ Moderação

Bedrock Guardrails pra LLM. Comprehend pra texto livre. Rekognition pra imagem/vídeo. Transcribe Toxicity pra áudio.

📊 Scoping Matrix

5 escopos da AWS pra GenAI. Quanto mais perto do self-trained, mais responsabilidade do cliente. Importante pra responsabilidade compartilhada.

📜 Linhagem

Source citation via Knowledge Bases. Data lineage via SageMaker Lineage Tracking + Glue Catalog. Model Cards documentam tudo.

🔐 Dados seguros

Trio mínimo: KMS (criptografia), IAM (acesso), CloudTrail (audit). Adiciona Macie pra PII e Config pra compliance contínuo.

🎯 Pegadinhas que caem na prova

  • "Modelo precisa explicar a decisão pra área regulada" → modelo mais simples (linear, árvore) OU caixa preta + Clarify/SHAP. Nunca apenas "use modelo mais complexo".
  • "Decisão sensível precisa de revisão humana" → Amazon A2I, sempre. Não confunda com Step Functions ou Lambda.
  • "Filtrar conteúdo gerado pelo LLM no Bedrock" → Bedrock Guardrails. Não é Comprehend, não é Rekognition.
  • "Detectar PII em buckets S3" → Macie. "Detectar PII em texto" → Comprehend DetectPiiEntities. São coisas diferentes.
  • "Empresa quer mostrar fontes nas respostas do chatbot" → Bedrock Knowledge Bases com source citations.
  • "Documentar bias e limitações do modelo" → SageMaker Model Cards. Não é só metadata, é documentação estruturada.
  • Generative AI Security Scoping Matrix tem 5 escopos. Decora os nomes (Consumer App, Enterprise App, Pre-trained, Fine-tuned, Self-trained).
